# ad-skipper

Android 免 root 广告跳过工具（无障碍服务实现）。当前版本 v2.1.2，另附 B 站内嵌广告的浏览器插件（见「浏览器插件」一节）。

## 已有模块

### B 站时间轴内嵌广告跳过（实测通过）

- 数据来源：社区库 SponsorBlock 镜像，`bsbsb.top → bsbsb.cc → www.bsbsb.xyz` 依次兜底
  （实测第一个镜像偶发 `unexpected end of stream`，第二个能续上），只使用 `sponsor` 分类
- **只对社区库已标注的视频生效**，不是万能开关：实测 53 条热门视频里 12 条有 `sponsor` 段
  （22.6%，明细见 `AI交流/T1_数据源覆盖.md`），命中的集中在解说/实况/恰饭类长视频；
  官方 PV、赛事回放、新闻、短视频基本没人标注，这些不会跳。三个镜像本身 0 失败、
  延迟 P50 347ms / P95 492ms，段数据完全一致，所以瓶颈在标注覆盖率而不是我们的接口
- 视频识别：优先取媒体会话元数据里的 BV（mediaId/mediaUri 命中就免搜索）；
  否则走 web 搜索接口 `x/web-interface/search/all/v2`（App 端 `x/v2/search` 会忽略关键词返回推荐流）。
  关键词按「前两个分句 → 首分句 → 整句」依次尝试，命中即停：实测只给首分句时
  B 站常召回一堆相似短视频、20 条里没有目标片，加上第二分句才召回；
  召回结果再做标题归一化相似度 + 时长 ±5s 打分，失败自动重试 2 次
- 监听服务销毁时要把 `OnActiveSessionsChangedListener` 从 `MediaSessionManager` 摘掉，
  否则回调继续 post 到主线程（属于泄漏，早期靠 `runCatching` 兜底所以看不出来）
- 会话销毁（切后台/重进）后必须重置已解析标题，否则重开同一视频走「标题未变」
  提前返回，片段库一直为空、整场失效
- 反过来，重开**同一条**视频时 bvid 没变，若 `skipped` 跨会话残留，这条视频的广告段
  第二次起永远不再跳。现在用「片段库从空变非空」认出新会话并清空 `skipped`/`attempts`，
  同时把待撤回状态和气泡一起重置（新会话里回到上一段广告的位置已经无意义）
- 切视频（上滑到下一条）时通知监听会先 `onDestroy` 关掉解析线程池，而媒体会话的
  `onMetadataChanged` 还会迟到一到：此时再往线程池提交任务会抛
  `RejectedExecutionException`，整个进程（含无障碍服务、正在显示的撤回气泡）一起没了。
  实测日志：跳过成功后 1.3 秒崩溃，栈顶 `BiliPlaybackWatcher.resolve(164)`。
  现在提交前先判 `io.isShutdown`（`resolve` 只在主线程调用，与 `onDestroy` 无竞态）。
  复验：自然播放 → 跳过 → B站自动切下一条 → 服务进程 pid 不变、`FATAL EXCEPTION` 0 行
- 进度读取：详情页内联播放器的 MediaSession 不更新 PlaybackState，改遍历播放器无障碍节点，
  用正则取形如 `09:14/29:43` 的进度文本（B 站的控件 id 会变，所以只认文本形态，不绑 id），
  控件隐藏时按时间外推；广告段附近会定时重新唤出
  控件读一次真实进度，避免暂停/手动拖动/3 倍速后外推漂移
- 暂停判定只认播放器按钮的 `contentDescription` 精确等于「播放」，页面里的
  「49.2万播放」这类文案不算暂停（否则会被误判为暂停而永不跳过）
- 判定为暂停时冻结外推基准（把 `posAt` 顶到当前时刻），否则恢复播放会带着「暂停了多久」的
  假位移直接冲过广告段，整场不再跳过；暂停期间只在广告段临近 90 秒内才唤控件、最多 3 次，
  其余每 5 秒静默重扫一次。实测 K40 暂停 60 秒：漂移 +0~+2 秒、期间零误跳，
  恢复后按剩余时间正常触发（理论 132 秒，实测 137 秒）
- 跳转：优先 `MediaController.transportControls.seekTo()`（会话 actions 含 SEEK_TO，
  实测生效且精确），失败退回拖动进度条。拖动必须从滑块中心（`left + 8dp` 半径）起手，
  落在轨道上 B 站不认；重试限 3 次，避免拖动失败时原地死循环刷屏
- 跳过目标必须留在片长内（`min(end + 300ms, dur − 1500ms)`）：广告一直顶到片尾时
  （实测 BV1imaN6tEK3，片段 11:07.318–13:28.277，`videoDuration` 就是 13:28.277），
  seek 越过片长会被 B 站当成「没有这条片段」，直接从 00:01 重播。修好后落点被压到
  13:27.5，一次会话 seek 就生效、不再退回拖动。这种片段跳完只剩 1.5 秒就播完、B 站随即切
  下一条视频，所以撤回气泡来不及点——属于素材本身没有正片可回，不是缺陷
- 跳过前 3 秒在底部弹出气泡倒计时（`3 秒后跳过广告`），可在设置里关闭倒计时
- 倒计时/撤回气泡本身是本 App 的窗口，会发出 `TYPE_WINDOW_STATE_CHANGED`；早期实现把它
  当成「切到了自己的 App」，前台包名被顶成自己 → B站扫描定时器一断链，而 B站详情页播放
  期间几乎没有无障碍事件，只能等 2 秒轮询里 30 秒兜底才复活。实测广告前 3 秒出现气泡后
  跳过晚了 31 秒（广告都播了半段）。现在：① 自己包的窗口事件改用活动窗口包名校正，
  不顶掉前台归属；② 定时器在停链前先用 `activeWindowPackage()` 核对一次，确认离开 B站
  才停（仍保持「非 B站 前台不常驻 1 秒唤醒」）。修后同一素材触发时机偏差 1 秒
- 跳过成功后气泡变为 `已跳过广告 撤回`，3 秒内点“撤回”可回到广告前 2 秒（防误跳），
  撤回后该广告段本视频内不再自动跳过；关闭倒计时不影响这个撤回入口
- 气泡依赖悬浮窗权限：未授予时 `SkipBubble.show()` 静默不显示（跳过本身照常生效），
  设置页有「悬浮窗：已开启/未开启」状态行和系统授权入口；实测 MIUI 覆盖安装后会把
  该权限重置，升级/重装 APK 后需要重新授予一次
- 广告前的跳过判断以真实进度为准，一次广告只跳一次；跳过结果用会话/界面读数双重校验

实测样例（Redmi K40 / Android 13，正式包回归）：

- BV1e1HA6RE1u，广告段 09:21.8–10:43.4。`会话 seek 09:19→10:42` → `seek 生效（会话），当前 10:44`
  → 点气泡「撤回」→ `撤回跳过，回到 09:17`，之后连续播放穿过广告段（11:13）不再二次跳过；
  会话 seek 无效时可见 `会话 seek 无效（08:36），改用拖动` → `拖动进度条 08:36→10:43` → `seek 生效`
- BV1njnn6yEMY，广告段 06:13.0–07:55.5。预置 04:01 后暂停 60 秒（漂移 +0 秒、期间无误跳）→
  恢复播放 137 秒后 `会话 seek 06:12→07:55` → `seek 生效（会话），当前 07:57` →
  0.1 秒内点「撤回」→ `撤回跳过，回到 06:10`，复读数与期望位置差 1 秒
- BV1imaN6tEK3（广告顶到片尾的边界素材，抽测两次）：一次会话 seek 就 `seek 生效（会话），当前 13:28`，
  不再出现修好前的 `会话 seek 无效…改用拖动` + 从 00:01 重播；落点被 `dur − 1500ms` 钳在片长内

调研过、实测后没有采纳的方案（都是拿真接口复现后淘汰的，避免以后再踩）：

- WBI 签名搜索：B 站 web 接口确实已上 WBI 风控，按官方算法（`finger/spi` 取 buvid3 →
  `nav` 取 img_key/sub_key → 54 位混淆表取前 32 → md5 得 `w_rid`）在本机跑通了，
  但换成桌面浏览器 UA 才返回结果，用 App 现在的移动端 UA 直接 0 条；
  同关键词下旧 `all/v2` 反而给 20 条、目标片排第 2。签名多两次往返换不来召回率，故不加
- 镜像 `bbzq.nkbe.top:9876`：`/api/skipSegments` 返回 404，现有三个镜像全部 200，不增节点
- 分 P 校正：社区库每条片段带 `cid`，理论上多 P 视频会拿到别的 P 的时间戳；
  实测抽了 6 个多 P 视频（195/11/149/194/94/181 P）片段数均为 0，
  即投稿基本只发生在单 P 视频，没有可误跳的数据，不做 cid 过滤
- `ACTION_SET_PROGRESS`：进度条节点确实支持该无障碍动作，但进度值只有 0–100，
  29 分钟视频一档 = 17.8 秒，精度远不如会话 seek 与拖动，不用

### 开屏广告跳过（启发式）

- 监控前台应用切换，在切换后 10 秒窗口内、每 300ms 扫一次 `跳过/关闭/跳过广告` 等文案与常见 id
- 激进口味：看到可点击的跳过控件就点；单次开屏最多点 2 下、两次之间冷却 1 秒，避免误点
- 无目标应用白名单时对所有 App 生效
- 纯图片开屏（无任何文字节点）兜底点右上角，但不作用于 B 站，避免视频页刚加载时误触
- 兜底点击前必须确认「开屏那个包仍是当前活动窗口」：输入法/负一屏弹出也会触发窗口切换，
  不校验就会点到用户正在看的页面（实测误点过 B 站搜索页的「取消」）
- 桌面（`com.miui.home`）、负一屏（`com.miui.personalassistant`）与系统 UI 一样列入排除名单

### 红果短剧广告跳过（v1.3.0）

- 目标包名：`com.phoenix.read`、`com.phoenix.read.tv`、`cn.xiaochuankeji.zhibo`
- 文字关键词 + 倒计时 + 广告 SDK 控件三重检测
- 命中广告后自动上滑进入下一段内容，并统计成功/失败
- 命中后延迟 1.5 秒才出手（等广告自己的倒计时走完），这期间用户可能已经切走：
  `dispatchGesture` 是**全局手势**，落点只看执行那一刻谁在前台。所以现在 `performSwipeUp()`
  出手前再核对一次活动窗口包名与息屏状态，红果不在前台就放弃这次滑动，日志打
  `滑动未执行：红果已不在前台`（不会再出现「已执行滑动」），避免手势打到用户刚切过去的 App
- 只在红果处于前台时轮询（省电）；检测用正则已预编译，2 秒一轮不产生额外对象

### 统一入口

- MainActivity 仪表盘：四项权限状态（无障碍 / 通知使用权 / 悬浮窗 / 电池优化）、四个开关、
  实时统计与日志
- 电池优化那一行会显示是否已加白名单，点「去设置」直接发起
  `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`（部分 ROM 没有直连弹窗时退回系统列表页）。
  MIUI 不加白名单会把后台服务冻结——K40 上实测过通知监听被省电策略拒绑定、
  重装后悬浮窗权限被回退，用户自己装机没有 adb 补权限的机会，所以必须有入口
- 底部版本号只有一个来源：运行时读安装包 `versionName`（布局和代码里不再各写一份，
  之前三处不一致必然漏改）
- 统计口径拆分：`B站跳过 X 次 · 撤回 Y 次（最近 …）`。撤回不再从跳过数里减一，
  避免出现「B站跳过 0 次（最近 已撤回）」这种反直觉文案

### 省电策略

- 息屏时不读取无障碍节点（`PowerManager.isInteractive` 门控）
- B 站 1 秒定时器只在 B 站处于前台时运行；停链前先用活动窗口包名校验一次，
  确认离开 B站 才停（不能靠 `foregroundPkg` 单独判断，它可能被别的窗口事件顶掉）
- 界面扫描频率按「离广告还有多远」分级：只有某个还没跳过的广告段在前方 90 秒内（或刚过段尾
  15 秒内）才 300ms 扫一次全树，其余时间 1 秒一次——B站 详情页弹幕/评论一直在刷内容变化事件，
  300ms 常驻扫描是前台主要开销（K40 实测：远端 1 秒档 0.7% 以下，广告附近密集档约 4.5%）
- 红果只在红果前台时 2 秒轮询一次；开屏检测只在 App 切换后的 10 秒窗口内进行
- 检测用正则全部预编译，轮询不额外分配正则对象
- 用户侧需要手动设置的项（不设置会莫名失效）：
  ① 无障碍服务；② 通知使用权（B站标题识别必需）；③ 悬浮窗（倒计时/撤回气泡必需）；
  ④ 电池优化选「无限制/不过滤」+ 允许自启动（小米/红米必需，否则后台会被冻结，
  服务掉线后表现为「权限都开了但就是不跳」）。MIUI 系统升级或覆盖安装后 ③ 常被重置

## 装机与自恢复

权限四步（缺一不可，仪表盘每一行都会显示当前状态）：无障碍 → 通知使用权 → 悬浮窗 →
电池优化「无限制」+ 允许自启动。

**覆盖安装或 MIUI 系统升级后必须重新确认悬浮窗权限**：MIUI 会把 `显示在其他应用上层` 重置为拒绝，
表现是「照样跳过但没有倒计时/撤回气泡」（我们只能静默失败）。

僵死态（权限看着都开着，但就是不跳）的恢复路径，按顺序试：

1. 设置 → 应用 → 跳广告工具 → **强行停止**，再重新打开 App（服务会重新绑定，绝大多数情况到这一步就好）；
2. 仍不行：把「无障碍」和「通知使用权」各关一次再开；
3. 再不行：重启手机（MIUI 偶发在休眠后不再回绑第三方无障碍服务）。

根因是服务进程与系统绑定状态不同步，不是配置丢失，force-stop 重开即可恢复。

已知限制（不是 bug）：

- 只对社区库**已标注**的视频生效，未标注的（官方 PV、赛事回放、新闻、短视频）不会跳
- 广告段顶到片尾的视频，撤回气泡可能来不及点就播完了（落点已钳在片尾前 1.5 秒，不会从头重播）
- 纯图片开屏的右上角兜底点击是启发式，可能误点；B站 已豁免
- 模拟器（MuMu）上红果不投剧内广告，红果分支只能在真机验收


## 浏览器插件（B 站内嵌广告，v1 实测通过）

`browser-extension/`，Chrome / Edge 的 MV3 扩展，只作用于 `www.bilibili.com/video/*`。
方案和 App 侧一致：同一串镜像（`bsbsb.top → bsbsb.cc → www.bsbsb.xyz`）、只认 `sponsor` 分类、
提前 3 秒倒计时、直接 seek 到段尾、3 秒内可点「撤回」回到广告前 2 秒、落点同样钳在片尾前 1.5 秒。

与 App 不同的三处（都是平台差异逼出来的，不是另起一套）：

- 浏览器里能直接读 `video.currentTime`，所以 App 那套「进度文本正则 + 时间外推 + 唤控件 + 拖进度条」
  兜底全部不需要；但内容脚本的 `setInterval` 在后台标签会被降频到 1 分钟一次（实测跳过晚了 4 分钟），
  所以主循环挂在 `timeupdate / seeked / play / pause / durationchange` 媒体事件上（约 4 次/秒，不受降频），
  250ms 定时器只做补充
- 取片段必须放 service worker：内容脚本跟页面吃 CORS，镜像不给 bilibili.com 发跨域头
- BV / cid 识别：`__INITIAL_STATE__` 在 MAIN world，内容脚本（isolated world）读不到，
  所以另有一条 `"world": "MAIN"` 的脚本把 `{bvid, cid}` 写进 `documentElement.dataset` 跨世界共享。
  **多 P 页面里 `videoData.cid` 恒等于第一 P**（实测 `?p=3` 时它还是 P1 的 cid），
  必须按 URL 的 `?p=` 去 `pages[]` 取当前 P，否则会拿别的分 P 的标注来跳
- 缓存按 BV 存、不分 cid（6 小时 TTL），切分 P 在本地过滤，省一次网络请求；
  404 与「200 + 空数组」都计为未命中
- 气泡整层 `pointer-events:none`，只有「撤回」按钮可点，不吃页面上的正常点击；
  全屏时挂进 `document.fullscreenElement` 子树（挂 `body` 的话全屏里看不见）
- 点工具栏图标是开关页：自动跳过 / 提前 3 秒提示两个开关、跳过与撤回计数、角标显示累计跳过次数，
  外加「数据源自检」——输入 BV 号直接看社区库里到底有没有标注，用来区分「插件坏了」和「这条没人标」

装机（未上扩展商店，只能开发者模式加载）：

1. 直接选仓库里的 `browser-extension/` 目录即可，**中文路径实测可用**（从 `C:\Users\...\跳广告工具\browser-extension`
   加载后主链路 12/12 全通；「纯 ASCII 路径」只是 App 打包时的要求，插件不需要）；
2. Edge 开 `edge://extensions`、Chrome 开 `chrome://extensions`，打开「开发人员模式」；
3. 「加载未打包的扩展」→ 选 `browser-extension` 目录；
4. 打开任意 B 站视频页即生效，无需登录、无需其它权限。

自动化验收踩坑（写给下次）：Chrome 156 稳定版已经**忽略** `--load-extension`（headless 与 headed
都只加载内置扩展，profile 里 `extensions.settings` 为 0 条）；Edge 156 还认，但只在**全新
user-data-dir** 时生效，复用旧 profile 会静默不注入。
