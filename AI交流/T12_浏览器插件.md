## 与 App 侧的方案对应

| 环节 | App（无障碍） | 插件 |
| --- | --- | --- |
| 数据源 | SponsorBlock 三镜像，只认 `sponsor` | 同一串镜像、同一分类 |
| 视频识别 | 媒体会话 mediaId → 标题搜索兜底 | URL 取 BV + `__INITIAL_STATE__` 取 cid（MAIN world 脚本桥接） |
| 进度读取 | 播放器控件进度文本正则 + 时间外推 + 唤控件/拖进度条兜底 | 直接 `video.currentTime`，无需外推 |
| 提前提示 | 3 秒倒计时气泡 | 同 |
| 跳过 | seek 到段尾，落点钳 `dur−1500ms` | 同（`TAIL_CLAMP_MS=1500`） |
| 撤回 | 3 秒窗口，回到 `start−2000ms` | 同（`UNDO_MS=3000` / `UNDO_BACK_MS=2000`） |
| 撤回后 | 该段留 `skipped`，本视频不再自动跳 | 同 |

## 三处必须不同的地方（平台差异，不是另起一套）

1. **跨域**：内容脚本跟页面吃 CORS，镜像不给 `bilibili.com` 发跨域头 → 取片段放 service worker，
   靠 `host_permissions` 直连。
2. **后台降频**：内容脚本的 `setInterval` 在隐藏标签被降到约 1 分钟一次，实测跳过晚了 4 分钟 →
   主循环改挂 `timeupdate/seeked/play/pause/durationchange` 媒体事件（约 4 次/秒，不受降频），
   250ms 定时器只做补充；seek 结果校验也从 `setTimeout` 改成 `pending.dueAt` + 事件驱动。
3. **isolated world**：`window.__INITIAL_STATE__` 读不到 → `"world": "MAIN"` 的脚本把 `{bvid, cid}`
   写进 `documentElement.dataset.adskipperVideo` 跨世界共享。顺带抓出一个真 bug：多 P 页面里
   `videoData.cid` 恒等于第一 P（`?p=3` 时仍是 P1 的 cid），必须按 URL 的 `?p=` 取 `pages[p-1].cid`，
   否则拿别的分 P 的标注来跳。

## 两条假 FAIL 的成因（都不是插件问题，记下来别再绕）

1. **「15 秒内没跳」**：其实是隐藏标签降频，最终在 4 分钟后跳了 —— 这次是真缺陷，已改成媒体事件驱动。
2. **「没有从 00:00 重播」FAIL（t=2.1）**：断言只看 `t`，没区分「同一视频重播」和「B站自动连播下一条」。
   取证方式是把 `location.href` + `video.duration` 一起采样：0.5s 时 `dur=null`（切集过渡），
   1s 时 href 已变成下一条 BV、dur=1925 → 属预期。断言改为 `t > 700 || BV 已变化`。

## 装机与限制（README 已写）

开发者模式「加载未打包的扩展」选仓库里的 `browser-extension/`（**中文路径实测可用**：从
`C:\Users\...\跳广告工具\browser-extension` 加载后主链路 12/12 全通；之前写的「必须先复制到纯 ASCII 路径」
是把 App 打包的要求串过来了，已纠正）。未上商店。
限制：只对已标注视频生效；只接 `sponsor`，网页贴片/充电片头不在范围；后台标签里 B站 自己会暂停，
暂停不跳是预期行为。

自动化侧环境结论（下次直接用）：Chrome 156 稳定版**忽略** `--load-extension`（headless 与 headed 都只加载
内置扩展，profile 的 `extensions.settings` 为 0 条）；Edge 156 认，但**只在全新 user-data-dir** 生效，
复用旧 profile 会静默不注入。unpacked 扩展 ID 由路径派生，固定路径 `C:/adskipper-ext` → ID `cagidbapapdcoghlmplihipfckcgdena`。
