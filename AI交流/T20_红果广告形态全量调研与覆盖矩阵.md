# T20 · 红果还有哪种广告没被认出来（三路调研 + 覆盖矩阵）

**先回答用户那句「不会到时候又出现那种不会跳的广告吧」：**
会。已确认还有 **4 类**我们认不出或不敢动，其中 **1 类是安全洞不是漏跳**（比漏跳更糟：可能把上滑变成进广告）。
这次的结论不是猜的，来源是社区规则原文 + 一个专门 Hook 红果广告的项目 + 穿山甲官方广告位文档 + 我们自己的静态反编译与真机取证。

---

## 一、我们现在的判据实际只覆盖「全屏盖住播放器」这一大家族

| 判据 | 触发条件（简化） | 机型相关性 |
|---|---|---|
| 提示条 | 树里有 `上滑继续(观看\|看)?短剧` / `继续上滑…短剧` 且非播放器控件 | 无关 |
| 倒计时 | 上面那条 + `\d+秒后` 钉出手时刻 | 无关 |
| 直播面 | 树里出现 `ttlive_player_render_view` | 无关 |
| 横屏几何 | 横屏 + 上左/上右/底条三区齐 + 「广告」角标 | 无关 |
| **广告层差分**（v2.7.5） | 竖屏 + 当前可见节点 ≤ 0.7×本机正片基线 + 无任何正片证据（集号/作者声明/全屏观看/保护词）+ 挂 3.2s | 基线自学，阈值机型无关 |

差分的价值在于**它不看广告长什么样，只看"播放器那一层被换掉了"**，所以画布自绘、Lynx 自渲染、纯图创意都能接住——这是它比前三条更耐久的原因。
但也正因为它只看"整层被换掉"，**半屏/浮层类广告它天生看不见**。

## 三、最要紧的三条（按严重度）

### 1. 差分不分 Activity，可能把「上滑」送进广告 —— 安全洞，优先级最高

源码里红果侧所有判据只看 **包名** `com.phoenix.read`（`AdSkipAccessibilityService.kt:56-60`、`:363`），
**没有任何一处按 Activity 收口**（`activeWindowPackage()` 返回的是包名，不是 Activity）。
而红果的激励视频、直播间引流页、商城页都跑在同一个包里。调研同时给出两条硬证据：

- 红果资源里就有一条文案 `string/g5t` = **「向上滑动进入全屏广告」**（T18 已抠出，我们把它写进了保护词表，但保护词只有在**那页有可读文案**时才生效，画布页读不到）；
- 社区实测反馈：**刷到直播间时向上滑 = 点击进入直播间**；试玩广告「要你上下划拉两下才领奖」。

也就是说：差分现在能在一个"不是剧间广告"的红果页面上，自己发起一次上滑。
**修法（v2.7.6，零点击、不改手势）**：`TYPE_WINDOW_STATE_CHANGED` 的 `event.className` 就是 Activity 名，记下来，
差分与直播面只在 `ShortSeriesActivity` / `ShortSeriesLandActivity` 生效；其它红果页面**只记录不动手**。

### 2. 半屏/浮层类（暂停广告、底部 Banner、商品卡、评论区、信息流）天生抓不到

它们不替换播放器那一层，节点差分看不见；要清掉只能**点关闭**，而"点"正是你定的底线（宁漏跳别误点）。
所以这一类**不是判据问题，是策略问题**，需要你拍板：
- 方案 A（保守，我建议）：加「识别 + 记录 + 不操作」，日志里能报"这屏有个暂停广告/Banner"，白天看数据量再决定要不要点；
- 方案 B（激进）：只对社区已验证的**具名关闭件**（`关闭此广告` / `c66`+`关闭` / 右上角 44×44 ImageView）走我们已有的开屏点击链路（同样过 `clickableAncestorAsButton` + 深链守护），黑名单式，不猜。

### 3. 形态会迁移，年底就有变化

调研到一条时间线：**红果金币激励 2026-11-01 起新用户下线、12-31 全量关停**，媒体口径随之是「红包类激励广告减少、广告时长与频次加码」。
也就是说 12 月底以后剧间中插会更密更长，试玩/直播/电商跳转类占比上升——差分能吃下全屏类这一条正好对口，
但「激励视频被误划」那条洞会更容易踩到。**建议每月跑一次通宵台账（脚本已固化在 `C:\adskipper-evidence\hg275\`）当哨兵。**

## 四、顺手拿到的两条社区实操情报（对我们有用）

1. **「立即领取」是金币挂件的全局文案，每个页面都在，不能单独当广告特征**（另一份红果脚本项目的明确结论）——
   和我们昨晚抽帧看到的「415金币 / 立即领取」常驻正片完全一致。差分现在靠"可见节点数"把它挡住，
   这条印证了：**必须保留 `playerVisBase` 与 0.7 比例这道闸，绝不能改成按文案判**。
2. 有项目反馈**红果广告/推广页会吞掉无障碍手势**，所以他们改用 `input swipe`（需 ADB/Sheluku）为主通道。
   我们走 `dispatchGesture`，昨晚 12/12 复核都回「已离开广告」，暂时没踩到；但以后遇到"划了没动"要先怀疑这一条，
   别急着加判据。
