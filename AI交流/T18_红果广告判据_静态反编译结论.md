# T18 · 红果剧间广告判据：静态反编译 7.4.3.32 的结论

取证方式换了两条不用装我们 App 的路，都在 Mi 10（有人正在刷剧、只允许「抓」）上跑通：

1. **shell 只读采集**：`dumpsys activity top` 在播视频的窗口里 0.27 秒返回，且完整打印
   `View Hierarchy:`，每行带 **混淆资源 id + V/G/I 可见性 + 边界**。
   → 判据①②不用广告样本也能读；`uiautomator dump` 在播视频时必失败
   （`ERROR: could not get idle state.`，12.3 秒），这条只在广告是静态图页时才可能成。
2. **静态反编译**：`pm path` + `pull base.apk`（146 MB，0644 免 root）+ `aapt2 dump resources/xmltree`。
   两台机器的红果都是 **7.4.3.32**（Mi 10 lastUpdate 10-30 01:31 / K40 10-30 14:32），结论可直接用。

## 一、推翻性结论 1：社区 id 表 `ay0`/`i0t` 不是广告，抄了会乱点

`hg_resources.txt`（124 954 行资源表）实测：

| 名字 | 真实身份 | 证据 |
| --- | --- | --- |
| `id/ay0` = `0x7f110947` | 只被 **1 个**布局用：`res/r/bm5.xml`，是个普通 `View`，同层有 `SimpleDraweeView`+主副标题 → **推荐卡片** | 二进制搜 14 062 个 res XML，只有 bm5 引用 |
| `id/i0t` = `0x7f112f53` | 被 `res/r/b0c.xml`、`res/r/chz.xml` 用，是 `ScaleTextView text=string/a5`，同层有 `GenreScrollTabLayout`、`LatestTimerVideoRecyclerView`、`CommonErrorView` → **首页频道 tab 文字** | 同上 |

顺带：`layout/ay0`（`res/r/ay0.xml`）是**选集/详情面板**（含 `SlidingTabLayout`），
和 `id/ay0` 只是混淆器按类型各自编号撞名。**结论：GKD/ad-auto 那两张 id 表在 7.4.3.32 上对不上剧间广告，不能抄。**

## 三、推翻性结论 2（保命）：红果自己就有「上滑会进广告」的文案

`string/g5t` = **「向上滑动进入全屏广告」**（`0x7f06253b`，无布局引用 → 代码 setText）。
也就是说：**上滑这个手势在红果某些页是「进全屏广告」的入口**，不是「离开广告」。
这正好对上用户那条底线（宁可不跳，也不能被送进别的 App）。
所以判据必须分两类，不能只看「有广告字样就上滑」：

- **广告在播**（该上滑）：出现 `id/d2y`/`id/d30`/`id/d35`，或文案 `上滑继续(观看)?短剧`、`\d+s后可继续上滑观看短剧`
- **解锁卡**（禁止上滑）：出现 `id/jvs`/`id/c6_`/`id/khd`/`id/c6b`，或文案 `试看结束`、`看广告支持正版短剧`、`暂不解锁`、`开会员解锁全部`
  → 这一页唯一安全动作是点「重新试看」`id/c6b`，或直接不动；上滑 = 进全屏广告

## 五、更正：广告页分两层，「一个字都不进树」这句是旧注释，不是本轮实测

被用户问住了，重测之后更正。三个 xml 要分清：

| 来源 | 有 id | 有文字 | 本轮实测 |
| --- | --- | --- | --- |
| APK 静态布局 xml | 有 | 有 | 已抠出 `cyn`/`amr` 两张广告页全表（第二节） |
| `dumpsys activity top` | 有 | **没有** | 243 行 `TextView{`，0 行带 text；`--categories text`、`-c text`、`text`、`id,text` 全试过，字节数几乎不变，MIUI/Android 13 不打印正文 |
| **无障碍树**（我们服务读的，`uiautomator dump` 读的就是它） | 有 | **有** | K40 红果首页 166 个节点 / 17 条文字 / 13 条带 `com.phoenix.read:id/` / 22 个 clickable |

代码里那句「广告自身一个字都不进树」（`AdSkipAccessibilityService.kt:755`）是 v2.2 时代写的，
我当时直接引用没重测。**至少红果原生壳那层是进树的**：`上滑继续观看短剧`（`string/bxk`）
在 `res/r/amr.xml` 里就是普通 `TextView`，`试看结束，解锁后可观看完整内容`（`string/f8w`）
在 `res/r/cyn.xml` 里也是 `TextView`，都不是 Lynx 自绘。Lynx 只画广告创意本体。

所以判据优先级要反过来（原第一节末尾「不能当运行时判据用」的说法作废）：

1. **主判据走树**：搜文案 `上滑继续(观看|看)?(短剧|剧集)` + id `d2y`/`d30` → 判「广告在播」→ 上滑；
   树判定不吃截图，顺带能砍掉现在 800ms 一拍截图的开销（红果前台 CPU 37% 的大头之一）。
2. **否决判据走树**：搜到 `试看结束` / `看广告支持正版短剧` / id `jvs`/`c6_`/`khd` → 判「解锁卡」→
   **禁止上滑**（第三节：那页上滑 = 进全屏广告）。
3. **模板匹配降级为兜底**：万一某些广告整页是 Lynx（壳没显示文案），再退回现在的截图模板。

仍缺的验证（只此一条）：**广告时刻**这些原生壳文案/id 到底进不进树。首页能进不代表广告页能进，
必须拿一条真广告测，不能靠推。

## 七、拿旧的真广告截图复核手势坐标，发现一个可降风险的空档

用的是 10-31 存在 `AI交流/T14_广告截图留存/` 的两张 Mi 10 横屏真广告图（2340×1080）：

- `ad_land_1145_hit96.png`：京东「点击领券 / 跳转秋日神价节」可玩创意，**创意是居中竖视频，左右各约 1/3 屏是纯黑边**；
- `land_now.png`：图片类广告，底部一整条「私信咨询」CTA（约占 y 0.72-0.86H）。

对照代码 `performSwipeUp()`：起点 `x=0.5W`、`y 0.66H → 0.36H`。

- 底部 CTA 躲开了（0.66H 在它上面）；
- 但 **0.5W 这条竖线正穿广告创意的中心**（第一张的「点击领券」就在 0.5W 附近），
  也就是现在这一划全程压在可点创意上，只靠 500ms 慢拖 + 5 秒深链守护兜底。

已知实测坐标：横屏提示条 pill 在 `x 1564-1992、y 64-160`（0.67W-0.85W），「广告 ⌄」下拉在它右边。
所以横屏的安全划法是 **在左侧黑边里划**（约 `x 0.18W`、`y 0.55H → 0.20H`）：
黑边属于红果自己的 `SingleTouchFrameLayout`（实测满屏 0,0-2340,1080），翻页照样生效，但整段绕开创意。

这条只是「按图算出来的空档」，**没有真机验证过黑边不被广告 SDK 吃掉**，
所以先记着，等有剧间广告的机子时和 200~300ms 手势 A/B 一起做，不盲改。
