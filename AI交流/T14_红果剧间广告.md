## 2. 为什么旧方案全废（有现场证据，别再走回头路）

1. **无障碍树 = 整叠页面并集**。广告页在屏时长这样：
   - 树里：`全屏观看 | 发弹幕 | 班般的甜蜜爱情第一季 | 第12集 | … | 选集 | · 已完结 · 全167集`（68 条，`窗=[3:systemui(3),3:systemui(11),1:readAF(68)]`）
   - 屏幕上：纯黑 + 「点击进入游戏」「上滑继续看短剧」「立即领取/6283金币」
   - 更离谱的一次：屏幕是三国杀游戏广告，`uiautomator dump` 出来的是**半小时前**另一部剧的「班般的甜蜜爱情第一季 第3集」。
   → 任何「关键词/文案塌缩/集数变化」判定读到的都是旧页面，**必然误伤**。
2. **实测误伤**：`detectAd` 的倒计时策略把页面上的裸数字 `2` 当广告（`matchesAdCountdown` 对长度 1 的数字没拦住），
   连续滑 4 次把正在看的剧集刷走、跳到了「推荐」信息流。该策略已删。
3. **黑屏判定不通用**：同一广告位有两种形态——全黑页 dark 98.8% / bright 0.9%；
   亮色游戏广告（三国杀）dark 很低。正常播放 dark 65–75% / bright 4–15%。黑屏阈值余量太小，已弃用。

## 3. 现在怎么判（实现摘要）

- 触发条件：前台包名 ∈ 红果包列表，每 2s 截一帧（`takeScreenshot`，需 API 30+ / `canTakeScreenshot`）。
- **多模板池**：`assets/ad_hint.png`（312×32「上滑继续看短剧」）、`ad_hint2.png`（384×64「上滑继续观看短剧」，取自
  20:23 家装广告页 OCR 位置 414–727 / 2107–2151 + 左侧箭头，裁 (342,2094,726,2158) 整除 4）。
  各自二值化（luminance>150）→ 4×4 降采样成 cell 网格（78×8 / 96×16）。
- **底部大范围搜索**（`matchHint`）：提示条锚定「距屏幕底 130–340px、x 346–756（1080 基准，按宽高缩放）」，
  区域整体预降采样 → 对每个模板 cell 网格粗搜（cell 步长）→ 在粗搜最佳点 ±cell 像素内 **1px 精搜**（NCC 对 1–2px
  位移敏感，粗搜网格会错过精确位置），取全部模板的最佳分。
- `score ≥ 0.85` 连续 **2 拍** → `onAdDetected` → 1.5s 后上滑（y 0.7→0.3，300ms）→ 2s 后复核（分数 < 0.85 判成功）。
- 截图系统最小间隔 1.2s + 单飞标志 + 错开一拍重试。
- 红果文字判定整体关掉；`detectAdFor` 只对抖音返回角标判定（保留）。

### 标定数据（离线 NCC）
| 截图 | 旧算法(固定坐标单模板) | 新算法(大范围双模板) |
|------|------|------|
| 黑屏广告 ×2 / 亮色游戏广告 | 1.00 | —（同模板，行为一致） |
| 正常播放 ×12 | ≤0.147 | ≤0.147（底部低相似区仍低） |
| 剧集详情页 / 剧场页 / 推荐信息流 | 0.50 / 0.275 / ≤0.127 | — |
| **「上滑继续观看短剧」变体广告页（20:23）** | **0.120** | **1.000**（精搜命中） |
| t1 × t2 模板互匹配 | — | 0.027（互不干扰） |

> 结论：旧方案漏跳根因 = 单模板只认一种排版 + 提示条 y 随渲染浮动（距底 185–298px），±20px 窗口兜不住。
