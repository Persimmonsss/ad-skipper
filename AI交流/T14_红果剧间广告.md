## 2. 为什么旧方案全废（有现场证据，别再走回头路）

1. **无障碍树 = 整叠页面并集**。广告页在屏时长这样：
   - 树里：`全屏观看 | 发弹幕 | 班般的甜蜜爱情第一季 | 第12集 | … | 选集 | · 已完结 · 全167集`（68 条，`窗=[3:systemui(3),3:systemui(11),1:readAF(68)]`）
   - 屏幕上：纯黑 + 「点击进入游戏」「上滑继续看短剧」「立即领取/6283金币」
   - 更离谱的一次：屏幕是三国杀游戏广告，`uiautomator dump` 出来的是**半小时前**另一部剧的「班般的甜蜜爱情第一季 第3集」。
   → 任何「关键词/文案塌缩/集数变化」判定读到的都是旧页面，**必然误伤**。
2. **实测误伤**：`detectAd` 的倒计时策略把页面上的裸数字 `2` 当广告（`matchesAdCountdown` 对长度 1 的数字没拦住），
   连续滑 4 次把正在看的剧集刷走、跳到了「推荐」信息流。该策略已删。
3. **黑屏判定不通用**：同一广告位有两种形态——全黑页 dark 98.8% / bright 0.9%；
   亮色游戏广告（三国杀）dark 很低。正常播放 dark 65–75% / bright 4–15%。黑屏阈值余量太小，已弃用。

## 3. 现在怎么判（实现摘要）

- 触发条件：前台包名 ∈ 红果包列表，每 2s 截一帧（`takeScreenshot`，需 API 30+ / `canTakeScreenshot`）。
- 取固定区域（1080×2340 基准：x 386, y 2010, w 312, h 32；x/w 按宽缩放、y 按高缩放），
  二值化（luminance>150）→ 4×4 像素降采样成 78×8 网格 → 与 `assets/ad_hint.png` 做 NCC。
- 在 ±24px(x)/±20px(y) 内取 9 个候选位移的最佳分。
- `score ≥ 0.85` 连续 **2 拍** → `onAdDetected("上滑继续看短剧")` → 1.5s 后 `dispatchGesture` 上滑（y 0.7→0.3，300ms）
  → 2s 后 `checkSwipeResult()` 再截一帧，`score ≥ 0.85` 判失败、否则成功。
- 截图有系统最小间隔（连拍报 `error 3`），已加 1.2s 全局间隔 + 单飞标志 + 错开一拍重试。
- 红果的**文字判定整体关掉**（`detectAdFor` 只对抖音返回角标判定），抖音角标逻辑保留。

## 6. 待办（按优先级）

1. **长时间 soak（必须）**：连播 10+ 分钟、跨 3 条以上广告，确认（a）零误滑（b）每条广告都跳得掉。
   目前只有 2 条广告 + 100 秒正常播放的证据。
2. **剧名/集数是脏的**：`extractDramaInfo` 从整叠树取最长文本，会把热评
   `熬到现在的 都是最幸福的人[爱慕][爽][爽][飞吻]` 或 `第4集 | 闺蜜沈妩和许茵…` 当剧名。
   建议：过滤含 `[`、`热评`、`展开`、`声明` 的文本；或优先匹配 `^.{4,40}第[一二三四五六七八九十\d]+季` / 取「…集 |」前缀之后的部分。
3. **跨机型验证**：模板按宽高比例定位，K40（1080×2400）未验证；若位置差太多，把 `padY` 放宽或改成按「视频底部」锚定。
4. 验证通过后：commit（4 个文件）→ 签正式包 → 桌面 APK → K40 覆盖安装 → 更新 `对话记录.txt` 与记忆。
5. 遗留：v2.2.2 之后的提交都未 push（代理未开，`127.0.0.1:21882` 不通）；抖音按用户要求暂停。
