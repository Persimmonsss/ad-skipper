## 严重级

### S1 【真实 bug】红果延迟滑动没有前台门控 —— 会误点其他 App
- **位置**：`AdSkipAccessibilityService.kt` → `processScreen()`（396-403 行）`handler.postDelayed({ performSwipeUp(); ... }, AD_WAIT_MS)`；`checkSwipeResult()`（400-402 行）再延迟 2000ms。
- **可达路径**：红果前台播放 → `detectAd()` 命中（文字关键词/倒计时/SDK 控件任一）→ `processScreen` post 延迟滑动 → **用户在此 1.5 秒内按 Home / 切到微信** → `performSwipeUp()` 在微信/桌面上执行全屏上滑手势。
- **为什么事件入口的门控没拦住**：`onAccessibilityEvent` 的 `if (pkg != foregroundPkg) return` 与 `rootNode.packageName != pkg` 校验只发生在**事件到达时**；延迟回调执行时没有任何校验。
- **建议**（伪码）：
  ```kotlin
  private fun performSwipeUp() {
      if (!screenOn() || !TARGET_PACKAGES.contains(foregroundPkg)) {
          logDebug("已离开红果，取消滑动"); return
      }
      ...
  }
  private fun checkSwipeResult() {
      if (!screenOn() || !TARGET_PACKAGES.contains(foregroundPkg)) { adSkipFailCount++; return }
      ...
  }
  ```
- **验证**：K40 真机，红果广告命中瞬间切回桌面，日志无「已执行滑动」；再测正常红果滑动链路不受影响。
- **状态**：已写入 `协作提问.md` P0-1，待主 agent 处理。

### S2 【已定位，修复待复验】本 App 气泡窗口事件顶掉 foregroundPkg
- **位置**：`onAccessibilityEvent:250-254` 对任何 `TYPE_WINDOW_STATE_CHANGED` 都 `foregroundPkg = pkg`；倒计时/撤回气泡是本 App 的 `TYPE_APPLICATION_OVERLAY` 窗口。
- **可达路径**：B站跳过前 3 秒气泡 addView → 本 App 窗口事件 → foregroundPkg 被覆盖成自己 → `biliTicker` 断链（foregroundPkg != BILI_PKG）→ B站 播放中无事件 → 30 秒兜底前不跳。
- **状态**：主 agent 已定位并在修（改 `biliTicker` 断链前核对活动窗口 + 自己窗口事件不顶前台包名）。回归通过后请在 T4 该条标 `【已复验】+ 日志证据`。

## 中级

### M1 开屏 10 秒窗口内 250ms 轮询的树遍历量
- **位置**：`splashTicker`（616-627 行）+ `scanSplashOnce`（651-695 行）。
- **可达路径**：任意目标 App 切前台 → 10 秒内每 ~300ms（SPLASH_SCAN_STEP_MS）扫一次 → 每次 `findSplashSkipNode` 深度 16 + `sampleList` 深度 14（限 12 条）遍历整棵树 → 10 秒约 33 次。
- **评估**：仅发生在 App 切换后 10 秒窗口，树大（WebView 广告）时单次遍历有开销，但窗口短、有 `SPLASH_MAX_CLICKS=2` 点击上限。**建议**：保持现状（省电可接受），验收时用 K40 实测开屏 App 冷启动的 CPU 增量留档即可。
- **状态**：无需改代码。

### M2 红果 2 秒轮询全树采集文本
- **位置**：`performPeriodicCheck` → `processScreen` → `collectAllTexts`（深度 15，无去重）。
- **可达路径**：红果前台常驻 → 每 2 秒整树遍历一次。
- **评估**：K40 实测前台约 0.3% 量级，符合省电红线；无去重只是多做几次 contains，非热点。
- **状态**：无需改代码。

### M3 开屏兜底盲点右上角（非 B站 App）
- **位置**：`scanSplashOnce:686-694`，`tapAt(0.88f, 0.085f)`。
- **可达路径**：App 冷启动 → 纯图片开屏（无文字/跳过节点）→ 2.5 秒后点右上角。**B站 已豁免**；其他 App 右上角若是功能按钮（如关闭按钮以外的"设置"图标）会被误点。
- **评估**：README 已声明激进策略（10 秒窗口 + 最多 2 次 + 冷却 1s），用户接受；不属于新缺陷。**验收时确认**：排除名单完整（systemui/launcher/settings/红果三包/MIUI 桌面/负一屏），`activeWindowPackage() != pkg` 校验生效（输入法/小窗弹出时不点）。
- **状态**：无需改代码。

### M4 通知重建频率
- **位置**：`logDebug()` → `updateNotification()`（239-243 行）；红果命中/滑动/开屏命中时高频调用。
- **可达路径**：红果广告命中 → logDebug("广告命中…") → rebuild + notify；滑动后 logDebug 又一次。连续广告页约 3-4 次/段。
- **评估**：通知 rebuild 有系统开销但低频（每段广告几次），可接受。**建议（可选）**：节流到每 2 秒最多重建一次。
- **状态**：可选优化，不阻塞。
