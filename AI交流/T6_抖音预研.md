# T6 · 抖音平台广告跳过可行性预研

> 负责人：豆包QA｜状态：预研结论（未实测，需真机确认时再补）
> 日期：2026-10-29｜目的：判断是否值得把「跳广告工具」扩展到抖音（aweme）

## 结论（先行）

**不建议为抖音加跳过功能，维持现状。** 抖音当前（2026-10）的广告形态对无障碍方案极不友好，投入产出比低，强行做会引入误操作风险。若要扩展，优先考虑的不是抖音，而是有开屏广告且无视频流广告的资讯/工具类 App。

## 1. 抖音广告形态（2026-10 现状）

| 形态 | 现状 | 可跳过性 |
|---|---|---|
| **开屏广告** | **已基本消失**。2026-06 京报网实测：抖音等主流 App 点开即达主页，已看不到开屏广告（监管指南要求第三方广告 SDK 显著标注摇一摇/提供关闭标志后，头部 App 直接取消） | 无对象可跳 |
| **视频流（信息流）广告** | 嵌入视频流，与正常内容高度相似（极小字标注「广告」）；部分产品（巨量引擎）为强制曝光**设计上不提供跳过按钮**，前几秒不可跳过 | 无「跳过」入口 |
| **评论/弹窗广告** | 与 B站 类似的卡片弹窗 | 理论上可复用弹窗检测，但抖音弹窗远少于其他 App |

## 2. 无障碍方案可行性矩阵

| 方案 | 可行性 | 风险 |
|---|---|---|
| 复用开屏模块（识别「跳过」按钮） | **低**：抖音已无开屏广告，无对象 | 无 |
| 识别「广告」角标 → 点击跳过 | **低**：无跳过按钮可点；点击可能进入广告落地页（反向操作） | 误触风险高 |
| 检测到广告视频 → 自动下滑 | **不可行**：下滑是抖音的正常内容切换手势，会把用户正在看的视频划走；无法区分「广告」与「正常内容」的播放器层级 | 严重误操作 |
| 检测到广告 → 静音/退出播放 | 技术上可做（无障碍调节音量），但用户感知为「广告还在播，只是没声」，价值低 | 行为不可预期 |
| 广告→自动点赞/收藏"欺骗算法"降频 | 无无障碍入口，不可靠 | 违反平台规则风险 |

## 3. 与现有架构的关系

- 现有 `AdSkipAccessibilityService` 的 TARGET_PACKAGES 白名单机制可随时加入抖音包名（`com.ss.android.ugc.aweme`），但**加进去意味着红果式 2 秒轮询 + 全树扫描会开始在抖音前台运行**——抖音视频流节点树大，省电预算会被吃掉，且大概率空转（无跳过对象）。
- 若强行加，唯一不误操作的用途是「开屏/弹窗检测」，而抖音开屏已消失。

## 4. 建议

1. **本轮不做抖音**；README 已知限制中已写明「仅对已标注视频生效」，可补充「抖音视频流广告无跳过入口，不做」。
2. 若用户确实需要抖音类场景，**更值得做的是：对有开屏广告的资讯类 App（贴吧/微博/知乎等 2026-06 京报网实测仍保留开屏广告）复用现有开屏模块**——只需加包名 + 验证排除名单，改动小、风险低。
3. 抖音方向若要重估：等出现「抖音开屏广告回归」或「信息流广告提供跳过/关闭入口」的信号再立项。
