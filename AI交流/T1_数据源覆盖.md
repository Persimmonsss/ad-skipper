## 结论（先行）

1. **镜像层没有任何问题，不需要再加数据源**：三个镜像 53/53 全部 HTTP 200、0 失败，延迟 P50=347ms / P95=492ms，三镜像段数据完全一致（12/12）。现有「bsbsb.top → bsbsb.cc → www.bsbsb.xyz」兜底设计足够，实测几乎用不上兜底。
2. **真正的瓶颈是社区库本身的标注覆盖率**：热门视频中只有 **12/53 = 22.6%** 有 sponsor 段。功能对"有标注的视频"100% 有效；对没标注的视频无能为力——这不是镜像问题，是社区库数据问题。
3. **覆盖率数字要结合内容类型看**：命中的 12 条全是典型「恰饭视频」（野生动物摄影、电竞赛事解说、游戏实况、美食探店、电视剧解说、动画）；没命中的大量是官方 PV（原神/崩铁/明日方舟 PV）、官方赛事回放、新闻、纯搞笑短视频——这些本来就没有赞助广告段。**对用户实际看的"解说/实况/影视"类内容，有效覆盖率显著高于 22.6%**，但本次样本没单独分层统计（见下一条建议）。
4. **文档勘误**：`AI交流/对接说明.md` §6 的示例 URL 编码是错的（`%5B%22sponsor%5D%5D` → 400，正确为 `%5B%22sponsor%22%5D`）。App 代码（`BiliSegmentRepo.kt:131` 用 URLEncoder）不受影响。已在 `协作提问.md` P1-4 提交。

## 给主 agent 的建议

1. **不加数据源**：三镜像已稳定且一致，加第四个源收益为零。若未来想提升覆盖率，方向是「数据源上游」：`sponsor.ajay.app`（SponsorBlock 官方）对 B站 视频也可能有标注，可以抽测官方接口与镜像的一致性——但这是增强项，不是交付必需。
2. **用户预期管理**：README 或 CHANGELOG 里建议加一句「仅对社区库已标注的视频生效，热门未标注视频无法跳过」，避免用户以为万能。
3. **可选优化**：若想提升命中率，可按「内容分区」统计覆盖率（影视解说/游戏实况 vs 官方 PV），确定目标用户群的真实覆盖率——本轮样本未分层，如需我再跑一轮分层抽样。
