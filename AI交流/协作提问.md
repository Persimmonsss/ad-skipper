## P0-1 【真实 bug · 紧急】红果延迟滑动没有前台门控
- **位置**：`AdSkipAccessibilityService.kt` → `processScreen()` 内 `handler.postDelayed({ performSwipeUp(); ... }, AD_WAIT_MS)`（约 396 行）与 `checkSwipeResult()` 的 `postDelayed(2000ms)`。
- **问题**：事件入口（onAccessibilityEvent）与轮询入口（performPeriodicCheck）都做了「前台包 / 活动窗口」校验，但**延迟回调执行时没有再次校验**。红果广告命中后 1.5 秒内用户切出红果（回桌面、切微信），`performSwipeUp()` 的滑动手势会打在别的 App 上——与之前修过的「跨 App 误触」是同一条漏网路径。
- **建议改法**（伪码）：`performSwipeUp()` 与 `checkSwipeResult()` 函数开头各加一道：
  ```kotlin
  if (!screenOn() || !TARGET_PACKAGES.contains(foregroundPkg)) {
      logDebug("已离开红果，取消本次滑动")
      return
  }
  ```
- **验证**：K40 真机红果广告命中瞬间立刻回桌面/开微信，日志不得出现「已执行滑动」。
- **状态**：待处理。

## P0-2 【真实 bug · 中】退出重进同一视频，广告段不再自动跳
- **位置**：`BiliUiSkip.kt` 的 `skipped` 集合只在 `resetIfVideoChanged()`（bvid 变化）时清空；`BiliPlaybackWatcher.kt` `onSessionDestroyed()` 只清 `currentTitle` 与片段库，**不清 BiliUiSkip 的 `skipped`**。
- **问题**：同一 bvid 的片段库重新解析后 `AdSegment.uuid` 相同（fetchSegments 有内存缓存，UUID 不变）→ `skipped.contains(uuid)` 命中 → 该广告段不再跳过。用户「看完退出 → 重进同一视频」第二次起广告不再自动跳。
- **建议改法**（伪码，二选一）：
  a) `BiliPlaybackWatcher.onSessionDestroyed()` 里通知 BiliUiSkip 清 `skipped`（暴露一个 `reset()`）；
  b) `BiliUiSkip.scanInto()` 检测到 `Stats.biliSegList` 从空变非空时清空 `skipped`。
- **验证**：真机跳过一次 → 退出视频 → 重进同一视频（续播或从头播）→ 广告段应再次触发跳过。
- **状态**：待处理。
