# T3 · 用户视角更新说明（CHANGELOG）

> 负责人：豆包QA｜基于 git 12 笔提交（18a945e → fb83d41），只写用户能感知的变化。

## v2.5.8（当前，versionCode=39）

### 变化
1. **红果滑动手势改回 300ms 快拖**（用户要求）。上一版是 500ms 慢拖。
   - 注意：300ms 正是 v2.4.0 出过事的那档速度——当时一次快速上滑被广告创意认成「打开落地页」，
     把用户带进了支付宝。这一版仍然开着 5 秒深链守护（跳到别的 App 自动 BACK 回来，最多 2 次），
     手势完成后 0.8 秒 / 2.2 秒各补一次前台检查。
   - 如果又出现跳走的情况，把 `performSwipeUp()` 里的 `300L` 改回 `500L` 就恢复慢拖。
2. 手势本身只占全程约 0.2 秒的差别。从广告出现到开始划走，主要时间在两头：
   连续两拍确认 + 竖屏挂够 700ms（约 0.9 秒），命中后再固定等 1.2 秒才出手。
   实测总量约 2.1~3.1 秒，典型 2.3 秒左右。

## v2.5.7（versionCode=38）

### 变化（红果剧间广告：不再靠截图识别）
1. **判据从「截图比对提示条」改成「直接读界面结构」**
   - 之前：每条广告都要先截一次画面，再二值化、和模板池比对；单是取图 ~200ms + 匹配 ~160ms，
     还要吃系统 333ms 的截图节流，广告明明已经挂出来了，判定却排在取图队列后面。
   - 现在：一次全树遍历同时给出「四个分区里可见的控件数」和屏上文案，广告层一挂出来
     连续两拍就确认。检测链路截图调用次数 0（24 轮实测）。
2. **广告出现到划走的等待大幅变短**：横屏旧链路实测 11~53 秒；现在广告渲染→命中 0.9~1.9 秒、
   命中→划走固定 1.2 秒，约 2 秒出手。
3. 日志量从探针期的 8.9MB 降到 222KB/24 轮。
4. **底线不变**：划动仍是 500ms 慢速拖动（不是快速甩动，快速甩动实测会被广告当成"打开落地页"），
   划完开 5 秒深链守护，出手前再核对一次红果还在前台。宁可这一条没跳过，也不把用户送进别的 App。

### 实测（Mi 10 竖屏 1080×2340，v2.5.5，24 轮慢速切集）
- 5 条剧间广告 **5/5 命中并复核跳过成功**，全程 0 次截图调用、0 次 FATAL，前台始终停在红果。
- 负样本：选集面板、切集动画、正片播放 **0 次误滑**。
- 竖屏判据是「广告层自带'上滑继续观看短剧'提示条 + 播放器'全屏观看'整块被盖掉」两条一起成立；
  只看到提示条那一拍（广告正在退场，两者同时可见）直接否掉。

### 未闭环（别当已验证）
- v2.5.6 收紧的竖屏判据与 v2.5.7 的「静态广告追拍」（广告不再推内容变化事件时，自己按 220ms 补采样）
  **还没有真广告正样本复验**——11-03 之后 Mi 10 无线调试掉线、K40 停在锁屏，样本中断。
- 横屏广告层没有可读文案，仍只按几何分区判，需挂够 1.5 秒才出手（切集动画会短暂凑齐三区）。

## v2.4.6（versionCode=26）

### 修复（都是"什么都没做"的静默失效）
1. **从红果切到别的 App，那条 App 的开屏广告不再漏跳**
   - 之前：从红果（播放器/首页）切出去冷启动别的 App，窗口事件到达后 5 毫秒内活动窗口还停在红果，
     "红果在前台就停止开屏扫描"这条规则当场把扫描关掉，那条开屏广告再没被扫过。
     实测从红果播放器冷启动小蚕，一个广告都没跳过。
   - 现在：切 App 的头 800 毫秒不算"红果还在前台"，扫描继续。同一路径复测：小蚕命中 `id/tv_skip`
     并复核「开屏已关闭」。
2. **红果在前台待久了，整条跳广告链路不再悄悄停摆**
   - 之前：前台归属只按窗口事件的包名更新，红果播放时系统窗口（`pkg=android`）每分钟来一次，
     前台包名被顶成 `android`；而"30 秒兜底刷新"每次都被新来的窗口事件推迟，永远等不到。
     事件过滤和轮询门控同时失效，7 分钟零巡检、零检测，日志一条错都不报。
   - 现在：窗口事件和每一拍巡检都以**活动窗口**为准。实测心跳日志里前台/活动恒为红果，
     巡检计数持续增长（30 秒 155 拍）。
3. **系统窗口（`pkg=android`）不再被当成"应用切换"**
   - 不再触发开屏扫描（原来每 250ms 刷一条"开屏扫描停止"），
     也不再被深链守护当成"跳到别的 App"而真的按返回（会把用户从播放器里踢出去）。
4. **点完广告输入法弹上来，不再被当成深链多按一次返回**（实测 B站 前贴片点完 0.7 秒搜狗输入法上来）。
5. 开屏扫描停止后不再每 250ms 把自己重新挂上（停止逻辑原来形同虚设）。

### 实测（Redmi K40）
- 开屏正样本：小蚕 / 歪麦 / 斗鱼 / 晓晓优选 **4/5 命中**，其中 3 条复核出「开屏已关闭」；
  越吃越有当日未投开屏（未命中，非漏跳）。**点完前台被带跑 0 次**。
- 开屏负样本：B站视频页 / MIUI 桌面 / 负一屏 / 通知栏 / 输入法 五类页面**误点 0 处**。
- 计数口径本轮：开屏 检测 4 ≥ 跳过 4 ≥ 成功 3。
- 红果：带探针包在播放器正片态连续采样 39 拍，树结构稳定（详见 `T17_探针取证结果与判据修正.md`）；
  **广告态样本仍未取到**（红果「基本功能模式」+ 未登录游客态不投剧间广告）。

## v2.4.5（versionCode=25）

### 修复（底线）
1. **开屏点「跳过」不再爬进全屏广告热区**
   - 之前：按控件 id 认出跳过按钮后，会沿父节点往上找「可点击」的祖先，最多 5 层、不问大小。
     实测晓晓优选的跳过文字往上爬到的可点容器铺满整屏 —— 那是整块广告热区，点下去直接拉起
     深链（被 MIUI 拦成「晓晓优选 想要打开 美团」），这就是"跳广告跳出别的 App"。
   - 现在：只点节点自己，或「同样只有按钮尺寸」的可点祖先（最多 3 层）；全屏热区一律不点，宁可漏跳。
2. **点完开屏也有深链守护**
   - 之前：守护只管红果滑动，开屏点击后前台被带到别的 App 不会退回来。
   - 现在：开屏点击后开 1.5 秒守护，前台跑到「不是刚才那个开屏 App」且不在白名单 → 立刻返回原应用。
     窗口只开 1.5 秒：实测深链在点完 260ms 就冒出来，而用户自己切 App 是常态，
     开 5 秒会把正常切换误判成深链（实测误伤两次返回）。
3. 守护白名单补上「当前开屏那个 App」：以前只放行目标应用和本应用，
   点掉晓晓优选自己的跳过按钮反而被自家守护当成深链按了返回。

### 实测（Redmi K40，用户指定的五个带开屏广告的 App）
- 正样本：小蚕 / 斗鱼 / 越吃越有 / 晓晓优选 4/5 命中跳过控件，斗鱼、晓晓优选复核出「开屏已关闭」；
  歪麦当日不投开屏广告（未命中，非漏跳）。点完前台仍是原 App，**深链 0 次、前台被带跑 0 次**。
- 负样本：B站视频页 / MIUI 桌面 / 负一屏 / 通知栏 / 输入法 五类页面误点 0 处；
  其中 2 处点到的是真正的广告跳过件（B站 前贴片 `id/count_down` 倒计时），属预期内。
- 计数口径本轮：开屏 检测 6 ≥ 跳过 6 ≥ 成功 4。

## v2.4.4（versionCode=24）

### 变化
1. **开屏计数口径修好了**：v2.4.3 只给「复核成功」补了计数，主路径漏计「检测」，实测出现
   「跳过 13 · 检测 3」这种跳过比检测还多的数字；现在认出可点的跳过控件就算一次检测，
   并且**同一条开屏的检测 / 跳过 / 成功各只计一次**（点两下、复核两次都不重复计），
   三档恒满足 检测 ≥ 跳过 ≥ 成功。
2. **仪表盘三行用词统一**：开屏那行原来写「点击」、红果写「滑动」，现在三行都是
   「检测 · 跳过 · 成功」，跟常驻通知与本文档一个口径。
3. **开屏只点看得见的窗口**：同一个 App 退到后台的窗口仍留在无障碍窗口并集里，实测在 B站
   搜索页点到了后台视频窗口残留的「跳过」倒计时。现在只认活动/聚焦窗口的树，
   代价是极少数画在非活动子窗口里的开屏会漏跳——按底线，宁可漏跳也不点看不见的控件。
4. 计数持久化真机确认：强行停止进程 → 重新绑定服务，`counters.xml` 数值一格不掉。
5. 实测（Redmi K40，v2.4.4）：冷启动京东、闲鱼命中开屏并复核「开屏已关闭」，点完前台仍是原 App；
   B站视频页 / MIUI 桌面 / 负一屏 / 通知栏 / 输入法 五类页面 0 误点。
   B站 视频页出现的 `开屏跳过 bili:跳过 5` 经查是 B站 自己的前贴片广告（`id/count_down` 带倒计时，
   跳完正片照常播），属该跳的广告、不是误点。

## v2.1.2（versionCode=5）

### 修复（用户可感知）
1. **暂停后恢复播放不再整场失去跳过**
   - 之前：视频暂停 60 秒以上，恢复播放后广告不跳了（进度外推在暂停期间漂移）。
   - 现在：暂停期间进度冻结，恢复后按真实位置继续算；每 5 秒静默重读一次进度校准。
2. **广告顶到视频片尾的视频不再"跳完从头重播"**
   - 之前：广告段结尾贴着片尾时，跳转目标越过片尾，seek 到 00:01 重新播放。
   - 现在：跳转目标强制钳在片尾前 1.5 秒内。
3. **跳过成功后自动切到下一条视频，App 不再整个闪退**
   - 之前：切视频时迟到的播放会话回调会触发解析线程池异常，把整个进程带崩（无障碍服务、撤回气泡一起没了）。
   - 现在：线程池关闭后回调会被安全丢弃。
4. **跳过倒计时气泡出现时，跳转不再延迟半段广告**
   - 之前：气泡窗口事件会干扰"当前前台应用"判断，导致跳过链路断 30 秒。
   - 现在：气泡不再影响前台归属，倒计时结束立即跳。

### 变化
- 仪表盘版本号改为自动读取（不再手写）。
- 统计文案改为「B站跳过 X 次 · 撤回 Y 次」，撤回不再让"跳过次数"变少。
- 仪表盘新增「电池优化」状态行：显示是否白名单，点「去设置」直达（MIUI 必需，见 T5）。
